# 05public 写作规则

本文件是本目录的写作规范。**在本目录新建/修改文章前,先读本文件。**

---

## 1. 目录定位

| 位置          | 用途                                                         |
| ----------- | ---------------------------------------------------------- |
| `05public/` | **对外发布的成稿**(只放成稿)。这里是站点的内容目录,也是 `blog-content` 仓库的全部内容,带完整 frontmatter,最后发布在我的博客Astra上 |
| `05draft/`  | **草稿区**:大纲、素材、半成品。不进站点、不进 `blog-content` 仓库,规则见 `05draft/AGENTS.md` |

**文件夹是唯一的开关**:文件待在 `05public/` 里就会上线,挪回 `05draft/`(或删掉)就下线。**frontmatter 里已经没有 `draft` 字段了。**

本文件 `AGENTS.md` 不是文章:站点的内容集合按文件名把它排除了(`content.config.ts` 里那条 `pattern: ['**/*.{md,mdx}', '!**/AGENTS.md']`),所以它**不需要任何 frontmatter 来"藏起来"**。但反过来说——**别在 `05public/` 里放别的非文章 md**,它会被当成文章发出去;真要放,就先把文件名加进那条排除规则。

## 2. 新建一篇文章的流程

1. **找素材**:用户提供素材,或者AI自己找素材。
2. **提炼知识点**:先列出这篇要讲清楚的点(写成大纲)。
3. **第一视角,用自己的话重写**:照着大纲重写一遍,**不逐句翻译、不整段照搬原文**。
4. **补上原文没有的**:形状表、坑、对比、工程直觉、串起来的逻辑。
5. **草稿先存 `05draft/`**:文件名 = 文章主题(文件名只决定 URL,草稿阶段叫得顺口就行)。
6. **定稿再搬进 `05public/`**:补齐 frontmatter 四字段(`title` 写文章标题,`pubDate` 填当天日期);图片连同 `assets/<文章名>/` 整个文件夹一起搬。详细步骤见 `05draft/AGENTS.md` 第 4 节。
7. **过一遍第 12 节的检查表**。

## 3. Frontmatter

字段顺序固定,四个字段:

```yaml
---
title:
description:
pubDate:
tags:
---
```

- `title`:**必填**。站点的页面标题、列表标题、浏览器标签页都用它,写给人看的原始标题,可以带英文大写(例:`Attention Is All You Need`);不写就退回 slug 化后的文件名——那会把英文转成小写,所以别依赖它。
- `description`:面向读者的摘要,不写"本文介绍了……"这种废话开头,直接说内容。
- `pubDate`:用**当天日期**,格式 `YYYY-MM-DD`。改稿不刷新日期,重写才刷新。
- `tags`:尽量从已有标签选择,实在没有再创造新的。

## 4. 文件命名

- 中文主题直接做文件名:`大模型的数学基础.md`、`RNN循环神经网络.md`。
- 英文专有名词保留原样:`Attention is all your need.md`、`Transformer架构.md`。
- 一篇文章一个文件。主题重复时**更新已有文件**,不要新建 `xxx2.md`。
- **文件名只决定 URL,显示标题看 `title`**:URL 取 `entry.id`,而 `entry.id` 是**文件名 slug 化**后的结果——中文原样保留,英文**转小写**,空格变 `-`,逗号之类的标点直接去掉。实测:`Attention is all your need.md` → `/blog/attention-is-all-your-need/`,`第一篇,进入AI.md` → `/blog/第一篇进入ai/`,`RNN循环神经网络.md` → `/blog/rnn循环神经网络/`。文件名还是得起得像样(URL 会被人看到),但**标题不用再迁就文件名,写 `title` 就行**。

## 5. 正文结构

- **正文不重复文章大标题,第一个标题直接就是第一节**,且**从 `##` 起分节**(节内子标题用 `###` / `####`,不跳级)。原因:文章页的主标题是布局用 `<h1>{title}</h1>` 渲染出来的(frontmatter 里的 `title`),正文再用 `#` 会跟主标题撞车——既重复,又因为全站 `h1` 都是 1.9rem,看起来和主标题一样大;把文章标题当成 `##` 写进正文,同样会让标题出现两次。
- 开头一段"前提概要"式的话:为什么写这篇、本文讲什么、适合谁看。
- 每节先讲**是什么 / 为什么**,再上公式、代码、表格。
- 结尾要有**小结**(长文必备),可以用一张 ASCII 框图或对比表把全文串起来。
- 篇幅:成稿一般 100 行以上才有发布价值;低于 50 行说明还没展开,回去补。

## 6. 语言风格

- **第一人称**,面向读者讲话:"我"、"大家"、"你"。不要论文腔、不要公文体。
- 工程直觉优先于严谨定义:先打比方说人话,再补严格表述。
- 关键结论用 **粗体** 标出来;一段只强调一两处,通篇加粗等于没加粗。
- 旁白、坑、经验,用 `注:` 开头单独成段,这是本博客的招牌写法。
- 术语首次出现给中英对照 + 缩写,例:`RNN(Recurrent Neural Network,循环神经网络)`。
- 标点沿用现有习惯:半角逗号 `,` 和句号 `.`,中文引号 `""`、书名号 `《》`、破折号 `——`。
- **不要**:空话套话("综上所述"、"众所周知")、过度谦虚("笔者才疏学浅")、Markdown 里的 HTML 标签。

## 7. 公式

- 行内:`$h_t$`;**独立公式必须独占一行,前后各留一个空行**:

```markdown
文字说明。

$$h_t = \tanh(x_t W_x + h_{t-1} W_h + b)$$

下一段文字。
```

- **公式一律用 LaTeX 重打,不放公式图片**(讲义里的图片公式要自己敲出来)。
- 公式后面跟一张符号表(符号 / 含义 / 形状),这是看懂公式最快的方式。
- 推导只保留"关键那一步"和"为什么这一步重要",不要整页堆公式。
- 涉及矩阵时说明形状约定(行向量还是列向量),别让读者猜。

## 8. 代码

- 代码块必须标语言:`python` / `bash` / `yaml` / `text`。
- 示例要能直接跑,关键形状/结果用注释写在旁边:

```python
output, h_n = rnn(x, h_0)
print(output.shape)   # torch.Size([32, 10, 256])
```

- 有版本差异、默认值陷阱的地方,在代码块后面补一条 `注:`。
- 不贴与主题无关的样板代码(完整训练脚本、argparse、日志配置等)。

## 9. 表格

- 参数表、形状表、方案对比表一律用 Markdown 表格,表头用中文。
- 表格前后各留空行,否则 Obsidian 和静态站点渲染不一致。

## 10. 图片

- **默认不配图。** 结构图优先用 LaTeX + 代码块里的 ASCII 展开图表达。
- 确实需要图片时:
  - **图片必须放在内容目录里**(发布时整个 `05public` 就是站点的内容目录,图片得跟着它走);放站点自己的 `public/` 下不会随内容发布,Obsidian 里也预览不到;
  - 草稿的图放 `05draft/assets/<文章名>/`,成稿的图放 `05public/assets/<文章名>/`;
  - **定稿时整个 `assets/<文章名>/` 文件夹跟着 md 一起搬**,两个目录同层,正文里的相对路径一个字都不用改;
  - 用**相对路径**:`![结构图](assets/RNN循环神经网络/结构.png)`;
  - 图片一律用标准 Markdown 语法,**不用** `![[embed]]`(站点不解析,会渲染成 `【嵌入:xxx】` 字面量);
  - EMF/WMF 等非浏览器格式,先用本机工具转成 PNG 再放。
- **课程讲义截图、带机构水印的图不要放进来**(版权 + 观感),只提炼文字和公式。

## 11. 来源与引用

- **不自动生成"来源与引用"小节。** 文章结尾默认就是"小结",不要自作主张加"本篇是我读完《XXX》后整理的""参考资料""延伸阅读""本文参考了…"这类段落。
- 只有两种情况才写:① 用户明确要求;② 正文里引用了具体数据、图表或他人原话,必须标明出处时——**就近标注**(链接或书名)即可,仍然不额外起一节。
- 素材来源自己心里有数就行,不必写进文章。

## 12. 发布前检查表

- [ ] **文件已经从 `05draft/` 搬到 `05public/` 根目录**(草稿不该留在这里),图片 `assets/<文章名>/` 一并搬过
- [ ] frontmatter 四字段齐全(含 **`title`**),`pubDate` 是当天日期
- [ ] 文件名与文章主题一致,无序号/日期后缀(文件名只决定 URL,别起太长太乱)
- [ ] 正文里没有 `#` 一级标题(`#` 只该出现在代码块注释里),分节从 `##` 起
- [ ] 全文围绕一个主题,大纲能一句话讲清
- [ ] 公式成对(每个公式都有配对的定界符,且**公式里不要写中文**),独立公式前后有空行
- [ ] 代码块都标了语言,能跑
- [ ] 没有 `[[ ]]`、`![[ ]]`、模板占位符残留(如 tp.date 那类写法)、HTML 标签
- [ ] 没留临时文件(`_tmp*`、`*.tmp`、中间脚本、导出的中间文本)
- [ ] 结尾有小结;**没有**多余的"来源/参考/延伸阅读"小节(除非用户明确要求)
- [ ] 与已有文章无主题重复(重复则合并更新)
- [ ] 本目录里除了 `AGENTS.md`,没有别的非文章 md(它会被当成文章发出去)

## 13. 给 AI 助手的执行约定

在本目录干活时,除了上面的写作规范,还要遵守:

1. **先读本文件再动手**;新建文章前先看目录里已有哪些文章,避免重复主题。
2. **重写,不搬运**:从 docx/ppt/网页提炼知识点,用自己的话组织;不逐句翻译、不整段复制原文。
3. **公式自己敲**:讲义里图片形式的公式,用 LaTeX 重打;推导要能自洽。
4. **不改别人已发布的文章**:除非明确要求修改某篇。改稿前先读原文件。
5. **不覆盖同名文件**:写之前确认不存在;存在就读出来增量更新。
6. **临时产物不留痕**:提取脚本、中间 txt、转换出的图片,用完即删或放系统临时目录。
7. **不碰版权素材**:课程截图、水印图、付费讲义原文,只提炼知识,不搬进来。
8. **前端事项不用请示**:frontmatter 的 `title`/`description`/`pubDate`/`tags` 按第 3 节自行填。
9. **完成后回报**:文件路径 + 结构大纲 + 覆盖了哪些点 + 哪些点没写/存疑。
10. **不在本目录写草稿**:新文章先写进 `05draft/`;把草稿搬进本目录(发布),只在用户明确说"定稿/发布"之后做。
